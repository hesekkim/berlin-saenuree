# 013. Posts MP4 동영상 업로드 용량 상향

- 상태: 완료
- 유형: 기능 개선
- 선행 작업: 010 새누리 소식 Posts

## 목적

CMS Posts에서 MP4 동영상을 업로드할 때 파일 크기 제한 때문에 실제 게시 가능한 영상이 거부되지 않도록 클라이언트·백엔드·로컬 환경 설정의 상한을 일치시킨다.

## 배경

- 작업 전 Posts 동영상 제한은 프론트엔드와 백엔드 서비스에서 50MiB였다.
- 작업 전 로컬 `backend/.env`에는 `APP_MEDIA_MAX_FILE_BYTES=20971520`(20MiB)이 설정되어 있어 공통 업로드 API가 더 작은 값으로 제한되었다.
- 업로드 대상 `Saenuri_MT_2022.mp4`의 실제 크기는 88,181,924바이트(약 84.1MiB, 88.2MB)다. 200MiB 상한에 충분히 들어간다.
- 따라서 파일을 처리하려면 Posts별 MP4 한도와 공통 서버 업로드 한도를 모두 올려야 한다. 멀티파트 요청 본문 상한에는 미들웨어가 1MiB 오버헤드를 더한다.

## 범위

1. Posts MP4 파일별 최대 크기를 200MiB(209,715,200바이트)로 설정한다.
2. 공통 미디어 업로드의 기본값, 로컬 `backend/.env`, `backend/.env.example` 설정을 200MiB로 맞춘다. 기존 환경 변수가 지정된 배포 환경은 별도로 값을 갱신해야 한다.
3. 사진의 파일별 10MiB 제한, 게시물당 동영상 1개 제한, 게시물당 전체 미디어 30개 제한은 유지한다.
4. CMS 작성·편집 화면의 한국어·영어·독일어 안내와 백엔드 환경설정 문서를 새 제한에 맞춘다.
5. 실제 업로드 파일을 저장소에 복사하거나 커밋하지 않는다.
6. CMS 및 공개 Posts에서 동영상 첫 프레임을 미리보기로 사용하며, 별도 썸네일 파일은 생성하지 않는다.
7. CMS 게시물 편집에서 업로드 진행률과 후처리 상태를 표시하고, 업로드 도중 저장·닫기·미디어 조작을 막는다.
8. 공개 Posts에서 이미지와 동영상 사이를 전환할 때 동영상이 애니메이션 중복 재생으로 깜빡이지 않도록 한다.

## 완료 조건

- 크기가 88,181,924바이트인 MP4가 Posts 작성 및 편집에서 클라이언트 검증을 통과한다.
- 200MiB를 넘는 MP4는 클라이언트와 서버 양쪽에서 거부된다.
- 백엔드 기본 미디어 한도와 Posts MP4 한도, 로컬 `.env`·`.env.example`이 200MiB로 일치한다. 배포 환경에서 값을 덮어쓰는 경우에도 200MiB로 설정하도록 문서화한다.
- 업로드 요청 본문 제한이 멀티파트 오버헤드를 포함해 허용 크기를 수용한다.
- 기존 사진 업로드 제한 및 게시물당 동영상 1개 규칙이 유지된다.
- 사용자에게 표시되는 한도 안내와 환경설정 문서가 실제 설정과 일치한다.
- CMS 편집 화면에서 업로드 진행률과 미디어 처리 상태가 표시되고, 작업 중 저장·닫기·미디어 조작이 방지된다.
- 동영상 첫 프레임이 CMS와 공개 Posts 미리보기에 사용되며, 별도 썸네일 저장 없이 동영상 전환 깜빡임이 방지된다.

## 완료 기록

- 초기 100MiB 제한을 프론트엔드와 백엔드 기본 설정에 반영한 뒤, 실제 업로드 파일에 여유를 둔 200MiB로 조정해 설정·예제·문서를 일치시켰다.
- CMS 동영상 업로드 진행률과 처리 상태, 브라우저 기반 첫 프레임 미리보기, 공개 페이지의 동영상 전환 동작을 보완했다.
- 업로드 크기 초과 검증과 게시물당 동영상 1개 제한 등 기존 제약을 유지했다.
