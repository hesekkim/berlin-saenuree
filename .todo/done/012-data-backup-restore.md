# 012. CMS 데이터 백업 및 복구

- 상태: 완료
- 우선순위: 높음
- 범위: 백엔드 파일 기반 데이터와 미디어를 백업·복구하고 CMS 설정에서 관리한다.

## 배경

현재 백엔드는 데이터베이스 대신 `backend/data/`에 JSON과 미디어 파일을 저장한다. Render 디스크 장애·초기화 또는 배포 실수로 데이터가 사라질 수 있으므로, 정기 백업뿐 아니라 관리자가 백업 파일을 별도로 내려받아 보관하고 새 디스크에 다시 올려 복구할 수 있어야 한다.

## 요구사항

### 백업 범위와 보관

- `data/`의 JSON, 페이지 데이터, CMS 설정, 게시물·휴지통, 팝업, 미디어 원본 및 파생 파일을 한 개의 ZIP으로 백업한다.
- OTP 임시 코드가 저장되는 `verification_codes.json`은 백업·복구에서 제외한다.
- ZIP에는 버전, 사이트 식별자, 생성 시각, 파일 목록 및 SHA-256을 포함하는 manifest를 둔다.
- 저장된 ZIP은 `data/` 외부의 백업 디렉터리에 보관한다.
- 자동 백업은 UTC 기준 월 1회(매월 1일) 생성한다. 실행이 누락되면 앱의 정기 유지보수에서 보충하고, 같은 달 중복 생성은 하지 않는다.
- 자동·수동·복구 직전 안전 백업을 통합해 최대 12개까지 보관하고, 초과 시 가장 오래된 백업부터 삭제한다.
- 백업이 Render 디스크와 함께 유실될 수 있음을 CMS에 안내한다. 장애 대비용으로 export 파일을 별도 위치에도 보관할 수 있어야 한다.

### 권한 및 보안

- 목록·생성·다운로드·업로드·복구·삭제는 모두 site admin 전용이다. UI 표시와 무관하게 백엔드에서 site admin 권한을 검증한다.
- 추가 환경변수 백업 비밀번호는 복구와 삭제에 요구한다. 목록, export, 수동 백업 생성, 업로드 검증에는 요구하지 않는다.
- 비밀번호가 서버에 설정되지 않았을 때 복구·삭제를 거부한다. 비밀번호를 로그나 저장소에 남기지 않는다.
- 업로드는 ZIP 형식, 경로, 파일 수·크기, manifest, 해시, 사이트 식별자를 검증한다. 경로 이동, 중복 엔트리, 심볼릭 링크, 암호화·손상·초과 용량 아카이브는 거부한다.
- 업로드 검증과 실제 복구는 분리한다. 업로드 후 manifest 요약을 보여주고, 관리자가 확인 및 비밀번호 입력을 완료해야 적용한다.
- 업로드 파일을 복구하기 직전에 현재 `data/`로 안전 백업을 먼저 만든다. 안전 백업 생성이 실패하면 복구를 시작하지 않는다.
- 복구는 staging 디렉터리에서 검증·추출한 뒤 데이터 디렉터리를 교체한다. 교체 실패 시 기존 디렉터리를 되돌린다.
- 업로드 임시 파일은 만료 후 정리한다. ZIP을 서버의 공개 경로에 노출하지 않는다.
- ZIP은 암호화되지 않으므로 다운로드본과 저장 위치의 접근을 제한한다.

### CMS UX

- site admin의 CMS 설정 화면에 백업 섹션과 목록을 추가한다.
- 목록에서 생성 시각·종류·크기를 확인하고, 수동 백업·다운로드·복구·삭제를 할 수 있다.
- ZIP 업로드 시 검증 결과를 먼저 보여주고, 복구 확인 대화상자에서 덮어쓰기와 복구 직전 안전 백업 생성을 안내한다.
- 진행 중 상태, 성공·실패 피드백을 제공하며, 복구 및 삭제에는 백업 비밀번호를 입력받는다.
- UI 문구는 기존 관리자 UI 언어와 동일하게 한국어·영어·독일어를 지원한다.

## 구현 범위

- 백엔드 설정, 백업 서비스, site-admin 전용 API, 업로드 본문 크기 제한, 유지보수 스케줄 연결
- CMS 설정 페이지 전용 API·hook·UI 및 번역
- 배포·환경 변수 가이드와 보안 문서
- 중요 로직 중심의 backend unit 및 frontend unit 테스트

## 완료 조건

- 월간 자동 백업은 같은 달 한 번만 생성되며, 전체 보관 수는 12개를 넘지 않는다.
- 백업에 JSON과 미디어가 포함되고 OTP 임시 코드는 포함되지 않는다.
- site admin 이외의 사용자는 모든 백업 API에서 거절된다.
- 복구·삭제는 올바른 환경변수 비밀번호가 없거나 틀리면 거절된다. export·수동 백업·업로드 검증은 추가 비밀번호 없이 동작한다.
- export한 ZIP을 새 디스크에 업로드해 검증·미리보기할 수 있고, 올바른 비밀번호로 복구하면 백업 파일의 콘텐츠와 미디어가 복원된다.
- 복구 직전 안전 백업을 생성할 수 없으면 현재 데이터는 변경되지 않는다. 복구 실패 시에도 기존 데이터를 보존한다.
- 악성·손상 ZIP 및 다른 사이트의 ZIP은 복구되지 않는다.
- `APP_DATA_ROOT` 영구 디스크 운영 가이드, 비밀번호 설정, 별도 위치 export 보관 안내가 문서화된다.

## 검증

- backend unit: 백업 범위, 파일 무결성, 월간 중복 방지, 12개 보관, 비밀번호·권한, ZIP 검증, 복구 전 안전 백업과 디렉터리 교체 실패 시 롤백
- API: 비 site admin 거부, 수동 백업·export·업로드 검증의 추가 비밀번호 비요구, 파괴적 작업의 비밀번호 요구 및 업로드 크기 제한
- frontend unit: 업로드 검증 후 확인, 비밀번호를 입력한 뒤 복구하는 상태 전환
- backend unit 전체와 frontend build·백업 hook 테스트 검증
