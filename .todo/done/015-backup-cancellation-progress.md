# 015. 백업 생성 진행 표시 및 취소

- 상태: 완료
- 유형: 기능 개선 및 안정성
- 선행 작업: 012 CMS 데이터 백업 및 복구

## 목적

데이터와 미디어가 많아 수동 백업에 시간이 걸릴 때 생성 상태를 분명하게 표시하고, 관리자가 진행 중인 백업을 취소할 수 있게 한다.

## 범위

1. 백업 생성 중 버튼 문구만 바꾸는 대신 `LoadingSpinner`와 진행 안내를 표시한다.
2. 진행 표시와 함께 취소 버튼을 제공하고, 취소 후 다른 백업 작업을 다시 시작할 수 있게 한다.
3. 취소 신호를 API 요청에서 백엔드 백업 생성 서비스까지 전달한다.
4. 백엔드는 파일 탐색과 ZIP 생성 중 취소 여부를 확인하고, 취소된 백업의 임시 파일을 정리한다.
5. 의도적인 요청 취소를 실패 토스트나 네트워크 재시도로 처리하지 않는다.
6. 완료·취소·오류 상태를 구분하고, 관리자 UI의 한국어·영어·독일어 문구를 유지한다.

## 완료 조건

- 백업 중 로딩 스피너와 진행 안내, 취소 버튼이 함께 표시된다.
- 취소하면 프런트엔드 요청이 중단되고 백엔드도 가능한 한 빠르게 ZIP 생성을 멈춘다.
- 취소된 백업은 목록에 남지 않고 임시 ZIP 파일도 남기지 않는다.
- 정상 완료와 실제 오류의 기존 피드백은 유지되며, 의도적인 취소는 오류로 알리지 않는다.
- 취소 이후 화면이 정상 상태로 돌아와 다른 백업 작업을 수행할 수 있다.

## 완료 기록

- `LoadingSpinner`에 인라인 표시를 추가해 백업 진행 안내와 취소 버튼을 나란히 표시했다.
- Axios `AbortSignal`을 사용해 요청 취소를 hook, API, 백엔드 서비스까지 연결하고 의도적인 취소의 재시도·오류 알림을 방지했다.
- 백엔드 ZIP 생성 중 취소를 확인하고 임시 파일을 정리한다. 요청 연결이 끊긴 경우에도 생성 작업이 정리될 때까지 대기한다.
- 백업 생성 취소와 임시 파일 정리 동작을 프런트엔드·백엔드 단위 테스트로 검증했다.
