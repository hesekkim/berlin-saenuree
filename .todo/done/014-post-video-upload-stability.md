# 014. Posts 원본 동영상 업로드 안정화

- 상태: 완료
- 유형: 기능 개선 및 안정성
- 선행 작업: 013 Posts MP4 동영상 업로드 용량 상향

## 목적

Posts 동영상 업로드 시 메모리와 임시 저장소 부담을 줄이고, 최대 200MiB 원본 MP4를 안정적으로 저장한다. 서버에서 동영상을 인코딩하거나 변환하지 않는다.

## 범위

1. Posts MP4 업로드와 공통 미디어 상한을 최대 200MiB로 설정한다.
2. Posts 동영상 원본 요청 본문을 청크 단위로 임시 디스크에 스트리밍하고 원본 바이트 그대로 영구 저장소로 이동한다.
3. 임시 디렉터리를 백업 대상 `data/` 밖에 두고, 저장소와 같은 파일시스템을 사용한다.
4. 비정상 종료로 남은 임시 업로드를 24시간 후 정리한다.
5. 업로드 요청 제한 시간을 늘리고 미디어 업로드 자동 네트워크 재시도를 비활성화한다.
6. 전송 진행률, 미디어 저장 상태, 사진 최적화 상태를 구분해 안내하고 중복 진행 표시를 없앤다.
7. 사용자가 취소한 동영상은 영구 저장하지 않는다.

## 완료 조건

- 200MiB 이하 원본 MP4가 변형 없이 저장·조회된다.
- 업로드 중 메모리 전체 적재 없이 임시 디스크 파일로 처리한다.
- 성공적으로 저장한 뒤 임시 업로드 파일을 정리하고, 취소된 업로드는 영구 파일을 남기지 않는다.
- 동영상 전송 실패를 자동 재시도하지 않으며 요청 제한 시간은 대용량 업로드를 수용한다.
- 편집 화면에서 전송률과 저장·사진 최적화 상태를 구분하고 중복 표시하지 않는다.
- 로컬·Render 설정 문서와 테스트가 구현 동작에 일치한다.

## 완료 기록

- 기본 미디어·Posts MP4 한도를 200MiB로 설정하고 프런트엔드 안내와 환경 문서를 맞췄다.
- Posts 동영상 업로드 API에 원본 요청 본문 직접 스트리밍 및 원본 파일 이동 저장을 적용했다.
- 임시 업로드 파일을 백업 대상 밖에 두고 24시간 후 정리하도록 했다.
- Posts 편집 중 미저장 동영상에 24시간 lease를 부여하고, 열린 편집기에서 주기적으로 갱신한다. 응답 유실 등으로 ID를 받지 못한 업로드는 lease 만료 후 자동 정리한다.
- 서버에서 동영상을 변환하지 않고, FFmpeg 없이 로컬과 배포 환경에서 원본을 저장한다.
- 동영상 업로드 요청 제한을 30분으로 늘리고 미디어 업로드 자동 재시도를 비활성화했다.
- 업로드 전송 중 진행률과 저장·사진 최적화 상태를 분리하고 단일 로딩 표시를 유지한다.
- 로컬·Render 설정 및 200MiB 원본 저장 정책을 문서화했다.

## 검증

- 미디어 업로드, 요청 크기 제한, 유지보수, Posts 서비스 백엔드 테스트 97개 통과.
- 관련 프런트엔드 단위 테스트 20개 통과.
- 프런트엔드 빌드와 ESLint 통과.
- `git diff --check` 통과.
