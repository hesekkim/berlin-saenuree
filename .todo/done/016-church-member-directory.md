# 016. 비공개 교회 명부 CMS

- 상태: 완료
- 유형: 기능 추가
- 선행 작업: 없음

## 목적

공개 사이트와 CMS 콘텐츠 편집 영역에 노출하지 않는 교회 명부 관리 기능을 제공한다. 권한에 따라 회원 정보를 조회·추가·수정·삭제하고, 데스크톱과 모바일에서 많은 회원을 효율적으로 관리할 수 있게 한다.

## 범위

1. `/admin/members` 관리자 페이지와 관리자 메뉴를 추가한다. 공개 라우트·Navbar·Footer·CMS 콘텐츠 편집 대상에서는 제외하고, CMS 계정 페이지 할당에서만 `members` 권한을 부여할 수 있게 한다.
2. `site_admin`은 항상 명부를 조회·관리할 수 있다. `page_admin`과 `page_manager`는 해당 CMS 계정에 명부 권한이 할당된 경우 조회할 수 있다. 권한이 있는 `page_admin`은 회원을 관리할 수 있지만 `page_manager`는 읽기 전용이다. 백엔드 API에서도 권한을 강제한다.
3. 회원 정보는 기존 JSON 저장·공용 잠금 패턴으로 공개 CMS 데이터와 분리해 보관하고, 기존 백업·복구 경로에서 보존한다.
4. 이름과 생년월일은 필수이며 이메일과 전화번호는 선택이다. 이름 공백, 이메일·전화번호 형식, 생년월일 형식 및 미래 날짜를 검증하고 오류를 해당 입력 필드에 표시한다.
5. 회원 추가·수정 Dialog와 단일 삭제 확인 Dialog를 제공한다. 추가 저장은 이름과 생년월일 입력 후에만 활성화하고, 수정 저장은 실제 변경이 있을 때만 활성화한다.
6. 목록은 데스크톱에서 헤더와 행의 열을 정렬해 한 줄로 표시한다. 모바일에서는 이름과 생년월일을 기본 표시하고 행을 펼쳐 이메일·전화번호를 확인한다. 편집·삭제 액션은 행 펼침 동작과 분리한다.
7. 회원 수와 추가 버튼을 제목 옆에 표시한다. 작은 화면과 한국어·영어·독일어 문구에서도 버튼 줄바꿈이나 가로 스크롤이 발생하지 않게 한다.
8. 관리자는 체크박스로 회원을 개별 또는 일괄 선택해 삭제할 수 있다. 현재 페이지 전체 선택, 선택 수 표시, 확인 Dialog, 부분 실패 시 실패 항목 유지 및 오류 안내를 지원한다.
9. 회원 목록은 페이지당 10명으로 나누고 이전·다음 버튼과 현재 페이지를 표시한다. 페이지 선택 상태는 페이지 간 유지하고, 전체 선택은 현재 페이지에만 적용한다. 페이지 전환 시 목록 상단으로 이동하고, 데이터 감소로 현재 페이지가 범위를 벗어나면 마지막 페이지로 조정한다.
10. 모바일 목록 헤더에서는 전체 선택 체크박스를 유지하면서 텍스트 라벨만 숨긴다. 선택 수와 삭제 버튼은 헤더 오른쪽에 두고, 데스크톱에서는 설명 문구와 같은 줄에 배치한다.
11. 정적 UI 문구와 로딩·빈 목록·오류·성공 상태를 한국어·영어·독일어로 제공한다.

## 완료 조건

- 명부는 공개 사이트와 CMS 콘텐츠 편집기에 노출되지 않고, 계정별 권한이 프런트엔드와 백엔드에서 동일하게 적용된다.
- `site_admin`과 권한이 할당된 `page_admin`은 회원을 추가·수정·삭제할 수 있고, 권한이 할당된 `page_manager`는 읽기만 가능하다.
- 이름·생년월일 누락 또는 잘못된 선택 입력값은 저장되지 않는다. 입력 오류는 각 필드에 표시되고, 추가·수정 저장 버튼은 요구된 조건에서만 활성화된다.
- 단일·일괄 삭제 모두 확인 후 처리한다. 일괄 삭제 일부가 실패하면 성공한 회원만 제거되고 실패한 회원은 재시도할 수 있도록 남는다.
- 모바일에서 이름·생년월일, 전체 선택 체크박스, 선택 수, 삭제 버튼을 사용할 수 있고 가로 스크롤이 발생하지 않는다. 데스크톱 목록 헤더와 행은 열이 정렬된다.
- 페이지 경계에서 이전·다음 버튼이 올바르게 비활성화되고 페이지 이동 후 새 목록의 상단이 보인다.
- 회원 데이터가 백업·복구 대상에 포함되고 모든 지원 언어에서 UI가 제공된다.

## 검증

- 백엔드 명부 단위 테스트: 입력 검증, JSON 저장·조회·수정·삭제, 역할별 API 접근, 백업 대상 포함 여부.
- 프런트엔드 단위 테스트: 권한별 UI, 입력·추가·수정·삭제, 일괄 선택, 페이지 이동 및 반응형 기능에 종속되지 않는 상태 전이.
- 프런트엔드 전체 테스트, 변경 파일 ESLint, TypeScript/Vite 빌드 및 `git diff --check`.

## 완료 기록

- `/admin/members`와 관리자 메뉴를 추가하고 공개 페이지 및 CMS 콘텐츠 페이지 권한 트리와 분리했다. CMS 계정 페이지 할당에서 `members` 권한을 관리할 수 있게 했다.
- 역할별 조회·관리 권한을 프런트엔드와 백엔드에 적용하고, 명부 데이터를 기존 저장·잠금·백업 경로에 연결했다.
- 필수·선택 입력 규칙, 필드별 유효성 오류, 회원 추가·수정 Dialog, 단일 삭제 확인 Dialog를 구현했다.
- 데스크톱 목록 열 정렬과 모바일 행 펼침·조작 버튼을 구현하고, 제목 옆 회원 수·추가 버튼, 다국어 축약 문구, 반응형 선택 도구를 정리했다.
- 체크박스 선택과 현재 페이지 전체 선택, 페이지 간 선택 유지, 일괄 삭제 및 부분 실패 처리를 구현했다. 작업 헤더 제목은 표시하지 않는다.
- 페이지당 10명 페이지네이션, 경계 버튼 상태, 목록 변경 후 페이지 조정 및 이전·다음 이동 시 페이지 상단 이동을 구현했다.
- 로컬에서 화면을 확인할 수 있도록 무시 대상 명부 JSON에 합성 mock 회원을 추가했으며 기존 레코드는 보존했다.

## 검증 결과

- 백엔드 명부 단위 테스트 6개 통과.
- 프런트엔드 전체 테스트 63개 파일, 333개 테스트 통과. 후속 페이지 이동·반응형 UI 변경 후 명부 대상 테스트 6개 통과.
- TypeScript 검사와 Vite 프로덕션 빌드 통과.
- 변경 파일 ESLint와 `git diff --check` 통과.
