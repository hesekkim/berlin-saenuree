# 017. 다음 달 생일자 월간 이메일

- 상태: 대기
- 유형: 기능 추가
- 선행 작업: 016 교회 명부 CMS 페이지

## 목적

관리자가 선택적으로 자동 발송을 켜고 끌 수 있도록 하고, 매월 마지막 일요일에 다음 달 생일자 명단을 여러 지정 이메일 주소로 보낸다.

## 범위

1. 명부 설정의 별도 관리 섹션에서 자동 발송을 켜고 끌 수 있게 한다. 설정 조회·변경은 `site_admin`으로 제한한다.
2. 수신 주소는 한 개 이상 여러 개 등록할 수 있게 한다. 주소별 형식 검증, 공백 제거, 대소문자 정규화, 중복 제거를 적용한다. 수신 주소 변경은 저장 후 다음 발송부터 반영한다.
3. 스케줄은 `Europe/Berlin` 기준 매월 마지막 일요일로 해석하고, 해당 월의 바로 다음 달 생일자만 포함한다.
4. 우선 이메일 본문에 이름과 생일을 포함한다. PDF 첨부는 별도 구현 비용을 확인한 뒤 결정하며, 본문 방식만으로도 기능을 완료할 수 있다.
5. 명부 전체나 개인 이메일·전화번호는 발송하지 않는다. 다음 달 생일자 목록만 지정 수신자에게 전달한다.
6. 기존 SMTP 서비스와 앱의 maintenance loop 패턴을 재사용하되, 발송 여부를 기록해 재시작·다중 실행 시 같은 대상 월이 중복 발송되지 않도록 한다.
7. 기능이 꺼져 있거나 수신 주소가 없으면 발송하지 않는다. SMTP 미설정·발송 실패는 로그와 관리자 UI에서 확인할 수 있어야 하며 실패를 성공으로 처리하지 않는다.

## 완료 조건

- `site_admin`이 발송을 켜고 끄며 수신 주소를 1개 이상 관리할 수 있다.
- 여러 주소에 같은 월간 생일 알림이 전달되며 빈 주소·잘못된 주소·중복 주소가 거부 또는 정규화된다.
- 시간대 전환, 월말 일요일, 1월에서 2월로 넘어가는 경우 등 경계 날짜가 올바르게 계산된다.
- 발송이 비활성화된 경우 또는 생일자가 없는 경우 메일이 발송되지 않는다.
- 재시작·반복 실행에도 동일 월의 중복 발송이 방지되고 발송 실패가 성공 처리되지 않는다.
- 이메일 본문에는 이름과 생일만 있으며 명부에 저장된 다른 개인정보가 포함되지 않는다.

## 검증

- 생일 대상 월 계산·마지막 일요일 판정·중복 발송 방지에 대한 백엔드 단위 테스트.
- 다중 수신 주소 설정 검증과 설정 권한 테스트.
- SMTP는 mock으로 대체하고 실제 이메일은 발송하지 않는다.
